# Backend

The backend trains and evaluates PPO policies for Gymnasium's
`BipedalWalker-v3` environment. 

It provides:

- curriculum-based training across four progressively harder stages;
- checkpoint discovery and policy evaluation through a FastAPI service;
- recorded evaluation videos and torque data for the frontend.

## Requirements

- Python 3.11 or newer
- [`uv`](https://docs.astral.sh/uv/)

Initialize the backend dependencies from this directory:

```powershell
uv init
uv sync
```

## Run the backend

Run commands from `backend\` so training artifacts are written to the expected
locations.

### Train a policy

```powershell
uv run python main.py train
```

Training defaults to 1,000,000 environment steps and a learning rate of
`3e-4`. Both values can be overridden:

```powershell
uv run python main.py train --total-steps 300000 --learning-rate 0.0003
```

Training advances when the average of the latest 100 episode scores reaches
the current stage's promotion threshold. It saves the best and final model
for each completed stage, along with a CSV training log.


### Start the API server

```powershell
uv run python main.py serve
```

The server listens on `http://127.0.0.1:8000` by default. Use a different port
with:

```powershell
uv run python main.py serve --port 8080
```

FastAPI's interactive documentation is available at
`http://127.0.0.1:8000/docs`.


## Backend layout

```text
backend/
├── main.py                 # CLI entry point 
├── api/server.py           # FastAPI routes and video serving
├── env/wrappers.py         # BipedalWalker env & evaluation helpers
├── models/actor_critic.py  # Actor-critic network and checkpoint loading
└── training/
    ├── curriculum.py       # Stage definitions and promotion logic
    ├── ppo_engine.py       # PPO rollout and optimization
    └── train.py            # Training loop, evaluation, and logging
```

## API surface

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Check service health |
| `GET` | `/api/checkpoints` | List available policy checkpoints |
| `GET` | `/api/curriculum` | Read the configured curriculum |
| `POST` | `/api/showdown` | Evaluate two policies under shared settings |
| `POST` | `/api/stress` | Evaluate one policy under selected settings |
| `GET` | `/videos/{file}` | Serve a generated evaluation video |

Evaluation responses include score, distance, step count, fall status, pass
status, effective physics settings, per-step actions, and a video URL.

## Generated artifacts

Training and evaluation create these directories/files under `backend\`:

- `checkpoints\*.pth` — model weights and observation-normalizer state;
- `checkpoints\curriculum_training_log.csv` — step and score history;
- `checkpoints\best_models.txt` — best-versus-final model summaries;
- `videos\*.mp4` — videos generated by showdown and stress evaluations.
